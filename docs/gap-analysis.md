## Bucket C Bugs With Repro Scenarios

### C1. Transfer/download gate is bypassed in Streamlit

- **Enforced here**: `publish_dataset()` computes a release decision and raises `PublicationBlockedError` unless verdict is `PASS` (`src/synth_platform/application/use_cases/publish_dataset.py:18-21`). CLI `generate` calls `publish_dataset()` before writing output (`src/synth_platform/interfaces/cli/app.py:43-63`). Database target write also refuses failed QA (`src/synth_platform/engine/generation/database/target_write_service.py:54-63`).
- **Bypassed here**: Schema UI always renders `st.download_button()` after generation, even if validation displayed an error (`src/synth_platform/interfaces/streamlit/pages/schema_twin.py:340-384`). PDF UI renders `Download synthetic twin PDF` before `Validate twin` can be clicked (`src/synth_platform/interfaces/streamlit/pages/pdf_twin.py:435-455`). Database UI exposes `Download Database B` after target write without a transfer approval/audit service (`src/synth_platform/interfaces/streamlit/pages/database_twin.py:880-893`).
- **Repro**: Run the Streamlit app, generate a Schema Twin, and use the ZIP download after the Validate section. The code path does not call `publish_dataset()` or `Quarantine.promote()`. For PDF Twin, upload/build/generate/render, then click `Download synthetic twin PDF` before clicking `Validate twin`; the download button appears first by control flow.

### C2. PDF "validate before download" ordering is inverted

- **Enforced here**: `run_document_validation()` is the real validation stage called only when the user clicks `Validate twin` (`src/synth_platform/interfaces/streamlit/pages/pdf_twin.py:440-455`).
- **Bypassed here**: `st.download_button("Download synthetic twin PDF", ...)` is rendered before the validation branch (`src/synth_platform/interfaces/streamlit/pages/pdf_twin.py:435-441`).
- **Repro**: In PDF Twin, upload a PDF, discover/build/bind/generate values, click `Build twin document`, then download `synthetic_twin.pdf` immediately. No validation report is required for that download.

### C3. Air-gapped LLM policy is contradicted by optional external providers

- **Enforced here**: The local-only adapter exists as `OllamaChatModel`, with a default localhost URL (`src/synth_platform/infrastructure/llm/ollama_chat.py:1-28`). The text UI toggles are off by default in session state (`src/synth_platform/interfaces/streamlit/pages/schema_twin.py:47-55`, `src/synth_platform/interfaces/streamlit/pages/database_twin.py:91-100`).
- **Bypassed here**: `TextGenerationConfig` defaults provider to `"openai"` (`src/synth_platform/engine/generation/text/generator.py:28-35`), `_call_provider()` uses OpenAI/Groq API keys and defaults Groq to `https://api.groq.com/openai/v1` (`src/synth_platform/engine/generation/text/generator.py:271-284`), and SmartValueGenerator defaults to provider `"groq"` with disk cache under `~/.mvp/value_cache` (`src/synth_platform/engine/generation/schema/smart_values.py:680-691`).
- **Repro**: Set `OPENAI_API_KEY` or `GROQ_API_KEY`, open Schema Twin or Database Twin with an eligible text-heavy column, enable the LLM toggle, and generate. The call path can leave the host through OpenAI/Groq instead of a self-hosted engine.

### C4. Text generation fallback path can crash instead of falling back

- **Enforced here**: `TextGenerationEngine.generate()` intends to fall back for ineligible columns (`src/synth_platform/engine/generation/text/generator.py:72-90`).
- **Broken here**: The ineligible branch calls `null_rng.random()` before `null_rng` is initialized at `src/synth_platform/engine/generation/text/generator.py:111-115`.
- **Repro**: Call `generate_text_column()` on a non-eligible `Column`, such as an integer or short text column, in an environment with dependencies installed. Expected fallback values; actual result should be `UnboundLocalError` from `null_rng`.

### C5. Schema validation can degrade to implicit success if the report is missing

- **Enforced here**: `run_schema_pipeline()` builds a validation report and returns it (`src/synth_platform/application/orchestration/schema/schema_driven.py:237-274`, `src/synth_platform/application/orchestration/schema/schema_driven.py:309-320`).
- **Contradicted here**: `SchemaModeResult.hard_checks_passed` returns `True` if no recognizable validation fields are present (`src/synth_platform/application/workflows/schema_twin.py:76-87`).
- **Repro**: Construct a `SchemaModeResult` or future pipeline result whose `pipeline.validation_report` is empty/malformed; the UI helper will treat it as passed. This is not exposed by the current happy path, but it is a latent false-positive validation bug.

## Additional Silent Inconsistencies Found

- **Docling runtime network risk is configuration-sensitive**: `_build_docling_converter()` returns plain `DocumentConverter()` when `DOCLING_SERVE_ARTIFACTS_PATH` is unset (`src/synth_platform/engine/documents/pdf/docling_engine.py:80-93`), and docs state Docling may fetch artifacts on first use (`docs/docling-integration.md:15-18`). Repro: choose Docling in PDF Twin on a machine without pre-fetched artifacts; model artifact fetching may occur outside the app's policy gate.
- **Audit logging exists but is not integrated into transfer paths**: `AuditLogger` has methods for sessions/generation/export operations (`src/synth_platform/engine/validation/schema/audit.py:1-80`), while Streamlit downloads use raw `st.download_button()` (`src/synth_platform/interfaces/streamlit/pages/schema_twin.py:378-384`, `src/synth_platform/interfaces/streamlit/pages/pdf_twin.py:435-438`, `src/synth_platform/interfaces/streamlit/pages/database_twin.py:892-893`). Repro: download any Streamlit artifact and no mandatory audit call is made on that path.
- **Durable orchestration is split**: generic application orchestration is scaffold (`src/synth_platform/application/orchestration/workflow.py:1`), while database/PDF stage orchestration exists separately in `WorkflowOrchestrator` (`src/synth_platform/engine/common/database/core/workflow_orchestrator.py:83-150`). Repro: building a fourth workflow must choose between copying UI/session-state gating or adopting the lower-level orchestrator; there is no single application orchestration surface.
- **Settings are not authoritative**: `Settings` contains `approved_output_root` and `staging_root` (`src/synth_platform/settings.py:14-15`), but Streamlit creates temp workdirs and direct output/download paths in page state (`src/synth_platform/interfaces/streamlit/pages/schema_twin.py:56-58`, `src/synth_platform/interfaces/streamlit/pages/database_twin.py:102-104`, `src/synth_platform/interfaces/streamlit/pages/pdf_twin.py:82-84`). Repro: change `SP_SEED` or staging/output settings and run Streamlit; page-level controls/workdirs still dominate.
- **API surface looks present but is unusable**: FastAPI app and routes exist as files, but are scaffold-only (`src/synth_platform/interfaces/api/app.py:1-4`, `src/synth_platform/interfaces/api/routes/generation.py:1-4`). Repro: install `.[api]` and try to route generation through `interfaces/api/app.py`; there is no app object or route implementation to enforce auth/gates.

## Start Here: Ordered Plan

1. **Fix C1/C2: unify export/download behind one transfer gate.** This is the highest-risk bug because the product claims validation/controlled transfer while Streamlit bypasses the gate. Create a shared `TransferService` or use case that requires validation status, optional approval metadata, and audit logging before returning downloadable bytes/paths. Replace Schema/PDF/Database `st.download_button()` paths with calls to that service.

2. **Fix C3: add an explicit LLM egress policy.** Centralize provider selection and make the default `off` or `local` in air-gapped mode. Fail closed if an external provider is requested without an explicit non-air-gapped config. Route optional text generation and SmartValueGenerator through the same policy.

3. **Fix C4/C5: repair validation/fallback false-success paths.** Move `null_rng` initialization before the ineligible text branch and add regression coverage. Change `SchemaModeResult.hard_checks_passed` so missing/malformed validation is not success.

4. **Done in Phase 4: Bucket A terminology cleanup.** `SeedReader`, `CategorySampler`, `Results page`, current step-flow implementation, and `TextColumn` naming are mapped in `docs/terminology-map.md` so future audits stop treating naming drift as missing engineering.

5. **Hold a decision meeting for Bucket D.** Do not sequence NeMo, Governance Hub, Section B, MCP tracing, central Context Synthesizer, feedback loop, or deployable security plane until ownership and target runtime are decided.

6. **Backlog B1: wire existing partial pieces closest to done.** First add PostgreSQL/non-SQLite UI support for Database Twin because SDK pieces already exist. Next wire local staging/quarantine into Streamlit once transfer gating exists.

7. **Backlog B2: finish product UI promises.** Add Settings and My Projects after settings/output/staging become authoritative. Add the richer progress screen after a shared event/job model exists.

8. **Backlog B3: add Customer Interaction Twin only after context/LLM decisions.** It can copy the current per-workflow pattern for a fast MVP, but if the team wants cross-domain consistency or strict LLM governance, those decisions should shape the design first.
