# Architecture Terminology Map

This map closes the Bucket A naming items from the gap analysis. These entries are architecture/documentation terms whose implementation already exists under different names; they are not missing components and should not be re-filed as feature gaps unless product scope changes.

## Closed Bucket A mappings

| Architecture term | Implementation mapping | Status |
| --- | --- | --- |
| `SeedReader` primitive | Maps to existing seeded generation and sampling controls, not a standalone class. Runtime defaults live in `Settings.seed` and `Settings.from_env()` (`src/synth_platform/settings.py:7-27`). Schema Mode accepts a UI seed and passes it to `generate_from_schema()` (`src/synth_platform/interfaces/streamlit/pages/schema_twin.py:249-269`), which applies it in `prepare_schema_for_generation()` and `PipelineConfig` (`src/synth_platform/application/workflows/schema_twin.py:456-519`). The schema pipeline also copies `PipelineConfig.seed` into the scaled schema (`src/synth_platform/application/orchestration/schema/schema_driven.py:76-89`). SQLite source sampling uses a deterministic `sp_seed_hash` function registered by `SqliteSource.__init__()` (`src/synth_platform/infrastructure/sources/sqlite.py:19-33`). | Closed by terminology alignment. No `SeedReader` class is required for current behavior. |
| `CategorySampler` primitive | Maps to categorical distribution parsing and override/rebalancing code, not a standalone sampler class. YAML `choices` and `probabilities` are accepted in `_parse_column()` (`src/synth_platform/engine/inference/schema/yaml_schema.py:245-314`). Database Twin exposes category distribution overrides in the Generate step (`src/synth_platform/interfaces/streamlit/pages/database_twin.py:642-720`). Rebalancing is implemented by `normalize_category_weights()`, `build_rebalanced_encoder()`, and `rebalance_column()` (`src/synth_platform/engine/training/database/adapters/category_rebalancing.py:35-68`). | Closed by terminology alignment. No `CategorySampler` class is required for current behavior. |
| `Results page` | Maps to inline workflow result sections rather than a separate route. Schema Mode renders Preview, Validate, and Download steps in one page (`src/synth_platform/interfaces/streamlit/pages/schema_twin.py:302-410`). Database Twin renders generation preview, QA validation, export, and download in its later steps (`src/synth_platform/interfaces/streamlit/pages/database_twin.py:752-920`). PDF Twin renders generated values, validation, and service-approved download inline (`src/synth_platform/interfaces/streamlit/pages/pdf_twin.py:387-539`). | Closed by terminology alignment. A separate Results route is a product/navigation choice, not a missing capability. |
| Front-end workflow step pattern | Maps to the existing step-based Streamlit flows for built workflows. Schema Mode declares progress steps and step containers (`src/synth_platform/interfaces/streamlit/pages/schema_twin.py:66-79`, `src/synth_platform/interfaces/streamlit/pages/schema_twin.py:246-410`). Database Twin declares a longer progress chain and step containers (`src/synth_platform/interfaces/streamlit/pages/database_twin.py:113-127`, `src/synth_platform/interfaces/streamlit/pages/database_twin.py:642-920`). Customer Interaction Twin remains separate backlog because that workflow is not built. |
| `TextColumn` YAML/code | Maps to the existing generic `Column` model with `type="text"` plus `distribution_params` such as `text_type`, `llm_text`, and `llm_enabled`, not a separate `TextColumn` class. YAML text/categorical field parsing happens in `_parse_column()` (`src/synth_platform/engine/inference/schema/yaml_schema.py:245-314`). Text-heavy LLM eligibility is centralized in `assess_column_eligibility()` (`src/synth_platform/engine/generation/text/eligibility.py:127-170`). The prior fallback crash was a Phase 3 bug; after that fix, the naming mismatch is documentation-only. |

## Scope notes

- `Document Twin` in broad architecture language should be read as `PDF Twin` for the current Streamlit product surface. Broader DOCX/image/general document support is still a real scope decision, so this is not marked Bucket A.
- `Governance Hub` and `Context Synthesizer` remain architecture decisions, not closed naming mismatches. Existing validation and context helpers are real code, but there is no separate hub or top-level cross-domain reconciler by that name.
